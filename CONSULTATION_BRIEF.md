# Бриф к встрече с экспертами (Первая ознакомительная встреча)

**Проект:** P2609-382 «Семантический навигатор» (расширение для VS Code)  
**Команда:** Разработчики Semantic Navigator  
**Цель встречи:** Представить базовый рабочий прототип (baseline), архитектуру и получить экспертную оценку и рекомендации по ключевым развилкам.

---

## 🧑‍💻 Эксперт 1: ML / Information Retrieval (IR) / NLP

### 1. Что уже реализовано в коде (Baseline):
- **Векторный поиск:** Косинусное сходство между векторами запроса и чанков (`engine/internal/search/vector.go`).
- **Лексический поиск:** Полнотекстовый поиск через нативную виртуальную таблицу SQLite `chunks_fts` с алгоритмом `BM25` и весами колонок: имя метода — 10.0, контекст класса — 5.0, тело — 1.0 (`engine/internal/storage/sqlite.go`).
- **Гибридный поиск (RRF):** Объединение рангов векторного поиска и FTS5 BM25 через формулу Reciprocal Rank Fusion:
  $$RRF(d) = \frac{W_{vec}}{k + \text{rank}_{vec}} + \frac{W_{bm25}}{k + \text{rank}_{bm25}}$$
- **Language-aware чанкинг C# и TS:** Нарезка кода на уровне методов с сохранением иерархии (`Namespace > Class > Method`), парсинг XML-документации (`/// <summary>`) и бюджетирование токенов (`engine/internal/chunker/chunker.go`).
- **Инкрементальный индекс в SQLite:** Хранение векторов в бинарных IEEE-754 BLOB, детекция изменений по SHA-256 хешам файлов.

### 2. Ключевые вопросы и развилки для консультации:
1. **Кросс-языковый поиск (RU-запрос → EN-код):**
   - *Вопрос:* Достаточно ли мультиязычных моделей эмбеддингов (например, `text-embedding-3-small`, `BGE-M3`) для поиска по смыслу русскими фразами по англоязычному коду, или же генерация гипотетического кода (HyDE / LLM query reformulation) даёт критический прирост качества, оправдывающий задержку в 300–500 мс?
2. **Стратегия обогащения контекста (AST / tree-sitter):**
   - *Вопрос:* Как наилучшим образом распределять лимит токенов (например, при бюджете 512–1024 токенов) между контекстным заголовком (сигнатура, docstring, базовый класс) и телом метода, чтобы не размывать фокус векторного представления? Стоит ли подтягивать типы аргументов и вызовы зависимостей?
3. **Настройка гибридного RRF:**
   - *Вопрос:* Какие веса ($W_{vec}, W_{bm25}$) и константу сглаживания $k$ (дефолт 60 vs 20–30) вы рекомендуете взять за отправную точку для кодовой базы? Стоит ли штрафовать чанки без точных лексических совпадений?
4. **Квантование векторов в `int8`:**
   - *Вопрос:* Практический опыт: насколько скалярное квантование векторов в `int8` (дающее 4-кратное сжатие размера базы SQLite) ухудшает метрики MRR@10 в задачах Code Search по сравнению с float32?
5. **Методика замера метрик качества:**
   - *Вопрос:* Каков оптимальный способ сформировать первичный ground-truth датасет запросов для валидации (например, 50–100 размеченных пар «запрос → метод»)? Как корректно рассчитывать Recall@5, MRR@10 и отсекать шум?

## 🎨 Эксперт 2: UX (юзабилити-исследование / Developer Experience)

### 1. Что уже реализовано в интерфейсе (Baseline):
- **Клавиатурный поиск QuickPick (`Cmd+Alt+F` / `Ctrl+Alt+F`):** Быстрый вызов всплывающего окна ввода запроса, дебаунс 350 мс, подсветка типа совпадения (`semantic`, `exact BM25`, `hybrid`).
- **Live Preview при стрелочной навигации:** При перемещении стрелками вверх/вниз по списку результатов редактор автоматически открывает и центрирует соответствующий файл в режиме превью без потери фокуса ввода.
- **Боковая панель (Sidebar TreeView):** Вкладка в Activity Bar, сохраняющая результаты последнего поиска для долговременного изучения и кликабельной навигации.
- **Статус-бар индикации фоновой индексации:** Ненавязчивая иконка с процентом выполнения (`$(sync~spin) Indexing: 45%`) в нижнем статус-баре, не блокирующая работу разработчика в редакторе и не создающая всплывающих модальных окон.

### 2. Ключевые вопросы и развилки для консультации:
1. **Сценарии быстрого поиска (QuickPick vs Webview / Боковая панель):**
   - *Вопрос:* Какой паттерн наиболее удобен для разработчика в ежедневной работе: легковесный QuickPick (как `Cmd+P`, быстро нашел — нажал Enter — окно закрылось) или закреплённая боковая панель с постоянным списком совпадений? Имеет ли смысл открывать отдельный полноэкранный Webview-таб для сложных поисковых сессий?
2. **Формат и информативность превью сниппетов:**
   - *Вопрос:* Как сделать так, чтобы разработчик за доли секунды понимал, почему результат попал в выдачу? Достаточно ли однострочного превью сигнатуры и пути с номером строки, или стоит показывать мини-дифф/раскрывающийся аккордеон с контекстом?
3. **Фоновая индексация и ненавязчивая обратная связь:**
   - *Вопрос:* Как лучше уведомлять пользователя о длительной первичной индексации большого репозитория, чтобы это не вызывало раздражения, но давало уверенность, что система работает? Достаточно ли статус-бара с тултипом или стоит использовать прогресс в правом нижнем углу (`vscode.window.withProgress`) с возможностью скрыть в фон?
4. **Обработка ошибок провайдера:**
   - *Вопрос:* Как лучше презентовать ошибки подключения к LLM/эмбеддинг провайдеру (истёкший ключ, 429 Rate Limit, отсутствие сети), чтобы разработчик мог исправить проблему в один клик?
