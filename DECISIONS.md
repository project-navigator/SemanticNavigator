# Semantic Navigator — технические решения

## 1. Архитектура — TypeScript + Go

Расширение на TypeScript, поисковый движок — на Go. Используем официальный API редактора и разделяем интерфейс и обработку данных. Go потому что важна производительность и возможность компиляции в нативные бинарники для разных ОС и архитектур.

## 2. Взаимодействие — JSON-RPC через stdio

Расширение запускает локальный Go-процесс и обменивается с ним сообщениями. Не нужен локальный HTTP-сервер и открытый порт.

## 3. Хранение индекса — SQLite

SQLite работает внутри процесса Go без отдельного сервера и хранит чанки, метаданные и эмбеддинги в базе в каталоге рабочего пространства VS Code (`storageUri`), упрощая установку расширения.

## 4. Хранилище VS Code — `storageUri` / `globalStorageUri`

Используем `storageUri` для базы SQLite рабочего пространства, а `globalStorageUri` — для общих служебных файлов; также сохраняем локальные настройки и состояние индекса. Пути предоставляет VS Code, поэтому не нужно выбирать системные директории вручную.

## 5. Поддерживаемые языки — обязательно C#

C# входит в MVP. Остальные языки добавляются по мере проверки качества извлечения символов и поиска. Используем официальные расширения VS Code для C# и других языков, чтобы переиспользовать их анализ кода и не дублировать его.

## 6. Разбиение кода — language-aware chunking

Основная единица индексации — метод или функция. Каждый чанк включает контекст класса: имя, пространство имён, сигнатуру и при необходимости документацию. Это повышает информативность эмбеддингов; исходный диапазон строк сохраняется для навигации.

## 7. Извлечение структуры — Language Services → Tree-sitter

Сначала используем `vscode.executeDocumentSymbolProvider` и провайдеры установленных языковых расширений. Если символы недоступны или недостаточны, применяем Tree-sitter. Так переиспользуем существующий анализ кода и сохраняем резервный вариант. Используем готовую библиотеку `go-tree-sitter` для Go.

## 8. Эмбеддинги — внешний OpenAI-совместимый API

Модель предоставляется отдельно; расширение не скачивает и не устанавливает её. Настраиваются URL, модель и при необходимости API-ключ. Можно подключить как удалённый сервис, так и локальный сервер с совместимым API.

## 9. Индексация — инкрементальная

Отслеживаем изменения файлов, сравниваем хеши чанков и пересчитываем только изменившиеся эмбеддинги. Это сокращает время обновления и число запросов к модели. Здесь есть задел на поддержку сервера с индексом, который будет хранить эмбеддинги и обрабатывать запросы от нескольких клиентов.

## 10. Поиск — векторный, с возможностью гибридного

Для MVP вычисляем косинусное сходство векторов в Go; `sqlite-vec` подключаем только при необходимости, подтверждённой бенчмарками. Архитектура допускает последующее объединение с лексическим поиском для точных имён символов.

## 11. Оценка качества — Recall@5, MRR@10 и задержка

На наборе запросов с размеченными релевантными фрагментами измеряем Recall@5 и MRR@10; отдельно — p50/p95 времени поиска и скорость индексации. Так оцениваем и релевантность, и производительность.

## 12. Публикация — VS Code Marketplace

Собираем расширение через VSIX и публикуем в Marketplace. Go-бинарники для поддерживаемых ОС и архитектур поставляются вместе с расширением или через платформенные пакеты; подключение к внешнему API эмбеддингов документируется отдельно.

## 13. Основные библиотеки

- **Go:** драйвер SQLite — хранение индекса (конкретная библиотека уточняется); `go-tree-sitter` — резервный синтаксический разбор.

- **TypeScript:** `vscode` — API редактора; `@vscode/vsce` — упаковка расширения.

**Открытые вопросы:** перечень языков помимо C#, выбор драйвера SQLite, идентификатор предоставленной модели и способ обнаружения её смены для переиндексации, точные правила разбиения крупных методов.
