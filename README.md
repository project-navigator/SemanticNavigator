# Семантический навигатор

Университетский проект **X2609-382**, команда **CodeBY**. Расширение VS Code на TypeScript и локальный поисковый движок на Go, лицензия MIT.

Поиск по описанию обычным текстом: QuickPick (`Cmd+Alt+F` / `Ctrl+Alt+F`), превью, переход к исходным строкам и боковая панель с полным списком последнего поиска и запросом. Движок объединяет косинусное сходство эмбеддингов с SQLite FTS5 BM25 через RRF. Качество русских запросов зависит от выбранной модели и пока **не измерено на реальном провайдере**.

## Сборка и установка на текущей машине

Команды выполняются из корня **SemanticNavigator**, а не родительской папки. Требуются **Go 1.26+** (см. `engine/go.mod`), **Node.js 22+**, npm и VS Code 1.85+. Проверено: macOS arm64, Go 1.26.5, Node 24.13.1, VS Code 1.143.1. На Windows эти shell-скрипты требуют Git Bash и установленных Windows Go/Node/VS Code.

```bash
./scripts/package.sh
code --install-extension dist/semantic-navigator-darwin-arm64.vsix
code demo/CodeBY.Shop
```

Скрипт собирает движок с `CGO_ENABLED=0`, копирует его в `extension/bin`, устанавливает закреплённые npm-зависимости через `npm ci`, компилирует TypeScript и создаёт платформенный VSIX в `dist/`. Для другой машины имя пакета содержит её платформу и архитектуру, например `linux-x64` или `win32-x64`. На других платформах сборка и установка пока не проверены. Go и Node нужны для сборки; пользователю готового VSIX они не требуются. Публикация в Marketplace не выполнялась.

Для сборки без упаковки:

```bash
./scripts/build.sh
```

Для отладки откройте **корень репозитория SemanticNavigator** в VS Code и нажмите F5 → `Launch Semantic Navigator`. Конфигурация `.vscode/launch.json` запускает сборку и открывает demo-проект в Extension Development Host.

## Настройка подключения

Сначала выберите и настройте согласованный провайдер. Затем включите индексацию в доверенной рабочей папке:

```json
{
  "semanticNavigator.providerUrl": "http://127.0.0.1:11434/v1",
  "semanticNavigator.model": "<идентификатор уже установленной модели эмбеддингов>",
  "semanticNavigator.apiKey": "",
  "semanticNavigator.enabled": true
}
```

Это пример формы настроек для локального OpenAI-совместимого сервера; конкретная модель и работа сервера должны быть проверены отдельно. URL — базовый адрес, движок добавляет `/embeddings`. Ключ необязателен для провайдера без авторизации; HTTP 401/403 по-прежнему считаются ошибкой. Удалённому провайдеру отправляются тексты чанков и запросы. По умолчанию `enabled=false`: активация расширения ничего не отправляет.

| Настройка | Значение по умолчанию | Назначение |
|---|---|---|
| `enabled` | `false` | Разрешить индексацию и отправку кода выбранному провайдеру |
| `providerUrl` | `https://api.openai.com/v1` | Базовый OpenAI-совместимый URL |
| `model` | `text-embedding-3-small` | Идентификатор модели |
| `apiKey` | пусто | Ключ, если требуется; не коммитьте секреты в workspace settings |
| `enginePath` | пусто | Явный путь к своему движку вместо встроенного |

Изменение настроек автоматически перезапускает движок. Смена URL/модели сбрасывает несовместимый индекс. Ключ не входит в отпечаток индекса. Если провайдер заменил модель под тем же именем, выполните `Semantic Navigator: Reindex Workspace`. Изменение размерности вектора обнаруживается и требует переиндексации; смену модели с той же размерностью и именем автоматически определить нельзя.

## Работа и ограничения

После включения дождитесь `Index ready`, откройте поиск, введите запрос, выберите результат стрелками и нажмите Enter. Все результаты последнего завершённого запроса остаются в боковой панели. Обновление файлов на диске запускает индексацию с задержкой 600 мс; события во время работы объединяются в следующий проход. Для несохранённых правок сначала сохраните файл.

Индексируется первая папка workspace: `.cs`, `.ts`, `.tsx`, `.js`, `.jsx`, `.go`, `.py`. Исключаются `.git`, `bin`, `obj`, `node_modules`, `dist`, `out`, `.vs`, `.idea` и симлинки. Правила `.gitignore` пока не читаются. SQLite хранится в `storageUri` VS Code. Методы C# и функции TS/JS/Go извлекаются эвристиками; для остальных случаев, включая Python, используются окна строк. **Language Services и Tree-sitter не подключены.** Сложный синтаксис может попадать в fallback или извлекаться неполно; это не полноценный AST-парсер.

Ранжирование возвращает ближайшие фрагменты без порога релевантности: непустой индекс может давать результаты даже для постороннего запроса. RRF score не является вероятностью. Пустая выдача показывает подсказку. Быстрый ввод не заменяет новую выдачу устаревшим ответом; встроенная фильтрация QuickPick не скрывает семантические результаты.

При 401/403 проверьте ключ и права; при 429 — квоту и повторите запрос позже; при сетевой ошибке — URL, доступность сервера и сеть. При ошибке индекса нажмите статус-бар для настроек, исправьте причину и выполните Reindex Workspace. Подробности: Output → Semantic Navigator. Если движок завершился или завис — проверьте `enginePath`, затем Reload Window. Запрос поиска к провайдеру ограничен 20 секундами, RPC поиска — 25; индексация одного файла — 60 секунд. Автоматических повторов HTTP нет.

## Проверки и оценка

```bash
(cd engine && go test -race ./...)
npm test --prefix extension
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/evaluate.py --mock --output evaluation/mock-results.json
# Отдельное окно VS Code с временным профилем и локальным mock:
./scripts/test-host.sh
# Проверка установки готового пакета в отдельный профиль:
./scripts/test-host.sh dist/semantic-navigator-darwin-arm64.vsix
# Необязательно, для проверки C#-демо нужен .NET SDK 8+:
dotnet build demo/CodeBY.Shop/CodeBY.Shop.csproj
```

Python 3.10+ нужен только оценщику. [Методика и реальный провайдер](evaluation/README.md), [архитектура](DECISIONS.md), [передача проекта](AGENT_HANDOVER.md), [встречи с экспертами](CONSULTATION_BRIEF.md).

Архитектуру TypeScript + Go необходимо согласовать с заказчиком: в паспорте указан TypeScript. Достижение 80 баллов не подтверждено одной технической проверкой; нужны реальная оценка поиска, ручная UX-проверка и материалы защиты.
