# Воспроизводимая оценка

Корпус `demo/CodeBY.Shop/ShopService.cs` — собственный открытый MIT-код: 12 методов английского C#. `queries.json` содержит 30 вручную размеченных запросов: 12 RU-описаний, 12 точных имён символов, 6 EN-описаний. Релевантность задаётся списком `относительный/путь.cs#SymbolName`. Для перегрузок потребуется расширить идентификатор сигнатурой/строками; в текущем демо их нет.

## Метрики

Для каждого запроса ищем top 10 через настоящий stdio RPC движка:

- **Hit@5**: 1, если хотя бы один релевантный фрагмент входит в первые пять; затем среднее по запросам.
- **Recall@5**: доля размеченных релевантных идентификаторов в первых пяти; затем среднее. При одной метке равен Hit@5.
- **MRR@10**: 1 / ранг первого релевантного результата в top 10, иначе 0; затем среднее.
- **p50/p95 latency**: nearest-rank процентиль wall-clock времени от отправки search RPC до получения ответа, включая эмбеддинг запроса и stdio, без debounce интерфейса. Один последовательный поиск на запрос, без прогревочного прогона. Отдельно записывается engineDurationMs и полное время индексации до done.

Есть общие значения, разрез ru/symbol/en и выдача каждого запроса. Отчёт сохраняет версию движка, модель, URL, время UTC, SHA-256 набора запросов и C#-исходников. Ключ не сохраняется. Для сравнения моделей держите одинаковыми корпус, запросы, RRF и условия запуска; повторите прогоны отдельно для оценки разброса задержки. Маленький синтетический корпус не доказывает качество на чужом репозитории. Метки и число отвлекающих методов нужно обсудить с экспертом.

## Запуск

Из корня репозитория, после `./scripts/build.sh`, Python 3.10+:

```bash
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/evaluate.py --mock --output evaluation/mock-results.json
```

Mock слушает только `127.0.0.1` на случайном порту, формирует детерминированные векторы хешированием слов. Это **не мультиязычная модель**. `mock-results.json` с `mode=MOCK_FUNCTIONAL_ONLY` подтверждает проходимость транспорта, индексации, ранжирования и подсчёта метрик. Его показатели качества и задержки нельзя выдавать за результаты реального сервиса. В текущем прогоне точные имена имеют MRR@10=1, но RU-совпадения при mock случайны.

Только после согласования провайдера и разрешения отправки корпуса:

```bash
# Для провайдера с авторизацией заранее задайте SEMANTIC_API_KEY безопасным способом.
python3 scripts/evaluate.py \
  --provider-url http://127.0.0.1:11434/v1 \
  --model <согласованная-модель> \
  --allow-code-upload \
  --output evaluation/results.local.json
```

Без ключа переменная не нужна. Конкретный сервер/модель из примера не устанавливаются скриптом. Для другого корпуса передайте `--workspace` и соответствующий `--dataset`. Для другого движка — `--engine`. Отдельный временный индекс создаётся автоматически, пользовательский индекс не затрагивается. Ошибка провайдера или движка завершает прогон, пропуски не считаются успешными запросами.

**Осталось:** реальный прогон, RU→EN качество и реальная задержка, более крупный независимый корпус, независимая проверка разметки, негативные запросы и подбор порога отказа от нерелевантной выдачи. Оптимизацию RRF/HyDE/парсера оценивать на отдельном от теста наборе; пока параметры не подбирались.
